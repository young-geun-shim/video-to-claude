# 1단계 — 글로 옮기기 · 화면 글자 인식 · 소리 받아쓰기 · 막힐 때

명령 앞의 `S` 는 `<이 스킬 폴더>/scripts` 이다.

## 받기 전에 본다

- 영상 정보의 언어와 자막 목록을 견준다. 원래 음성 언어의 받아쓰기(예 `ko-orig`)가 없고 다른 언어 받아쓰기만 있으면, 그것은 유튜브 자동 더빙의 받아쓰기다. 채널이 쓴 글은 화면에만 있을 수 있으니 곧바로 `fetch.sh --video` 로 영상을 받고 화면 글자 인식을 필수로 한다.
- 주소가 없는 영상(내 컴퓨터에 있는 mp4)은 `<작업 폴더>/원본영상/` 에 파일을 놓고 `원본자막/meta.json` 에 `title`(영상 이름)과 `duration`(길이, 초)을 적어 시작한다. `id` 와 `자막_출처.json` 은 없어도 된다. `id` 가 없으면 `원본영상/` 안 첫 파일 이름(확장자 뺌, 밑줄 앞까지)을 영상 번호로 쓰고, `자막_출처.json` 이 없으면 고른 자막이 없는 것으로 본다. 자막이 없으니 아래 「소리 받아쓰기」의 `transcribe.py` 로 가거나 화면 글자만 읽는다. 소리 받아쓰기 길은 `fetch.sh` 없이 `transcribe.py` 부터 돌리고, 소리가 든 파일을 `원본영상/` 에 두면 된다. (자동 받기 길은 없다.)
- `fetch.sh` 는 한 번에 영상 하나만 받는다. 재생목록 주소(`list=` 만 있고 `v=` 가 없는 주소)를 주면 「영상 하나 주소만 받는다」를 찍고 실패로 끝난다. 그때는 영상마다 주소를 따로 받아 하나씩 돌린다. `v=` 와 `list=` 가 같이 있는 주소는 그 영상 하나만 받는다.
- 원래 말 자막을 먼저 받은 뒤, 한국어 자막이 없으면 유튜브 자동 번역 한국어 자막을 한 번 더 시도한다. 사용자 언어는 환경 변수 `VIDEO_TO_CLAUDE_LANG`(예 `en`, `ja`, 기본 `ko`)으로 정한다. 개인 설정 파일(`video-to-claude.local.md`)은 스크립트가 읽지 않고 클로드가 읽는 글이라, 거기에 적은 언어는 클로드의 번역 · 글쓰기에만 걸리고 자막 고르기에는 걸리지 않는다. 자동 번역은 유튜브가 자주 막으므로 못 받아도 「자동 번역 자막은 못 받음 — 원문 자막으로 진행」을 찍고 이어 간다. 그때 번역은 클로드가 원문을 읽고 한다.
- 같은 작업 폴더에 이미 다른 영상이 들어 있는지 `fetch.sh` 가 견준다. 견줄 수 없으면 멈추고 여쭙는다. 같은 영상이 맞다고 사용자가 확인한 뒤에만 `--same-ok` 를 붙여 다시 돌린다.

## 글로 옮기기

```bash
python3 $S/subs_to_md.py "<작업 폴더>"     # 자막_전문.md + 원본과 한 줄씩 맞춰 보는 검산
python3 $S/merge.py "<작업 폴더>" [--from 초 --to 초 --suffix _1부]   # 영상_전체텍스트{접미}.md + 읽기용{접미}.md
```

- 검산이 「검산 통과」로 끝나야 다음으로 간다. 자막이 하나도 없으면 「옮긴 자막이 하나도 없다」가 찍히고 「검산 통과」는 안 나온다. 그때는 소리 받아쓰기나 화면 글자 인식으로 간다. 화면 글자만 있는 영상은 `merge.py` 의 화면 글자 검산 줄(「찍혀야 할」과 「찍힌」이 같음)이 통과 기준이다.
- `subs_to_md.py` 는 부분을 나눠도 자막 전부를 옮긴다. 부분만 읽는 것은 `merge.py --from --to` 가 한다. `--to` 시각 자체는 범위에 들어가지 않는다.
- 자막 이름표 = 원래 음성 언어 받아쓰기는 「발화 원문」, 다른 언어 받아쓰기는 「자동 더빙 받아쓰기」, 소리 받아쓰기(whisper)는 「발화 원문 · 소리 받아쓰기(whisper)」(`transcribe.py` 가 붙이는 이름표). 더빙 받아쓰기는 채널이 쓴 글이 아니다. 화면 글자 인식을 기다리는 동안 내용을 먼저 파악하는 데만 쓰고, `발표자방법.md` 의 원문 시각과 인용은 발표자의 원래 말(원래 음성 자막 · 소리 받아쓰기)과 화면 글자에서만 가져온다.
- 2단계는 `읽기용.md` 로 읽는다(부분이면 `읽기용_1부.md`). 합친 파일 `영상_전체텍스트.md` 는 자막 여러 벌이 다 들어 있어 원본 확인용이다.
- 원래 음성 받아쓰기가 있고 화면 글자가 필요 없으면 자막만 합친 파일로 곧바로 2단계를 시작한다.
- 화면 글자가 필요한지 정하는 기준 = 발표자가 슬라이드나 화면을 보여 주며 말한 영상이거나 자막에 안 나오는 글이 화면에 있으면 필요하다. 장면 그림을 직접 보고 정한다. 슬라이드에만 있는 방법이 빠지는 것이 이 판단의 가장 큰 위험이다.

## 소리 받아쓰기 (자막이 없는 영상)

```bash
bash $S/check_env.sh                                    # 소리 받아쓰기 부품(faster-whisper)도 점검한다. 없으면 「알림」과 설치 명령이 나온다(실패로 세지 않는다)
bash $S/fetch.sh "<주소>" "<작업 폴더>" --video         # 영상 파일이 있어야 소리를 뽑는다(주소가 없는 영상은 이 줄을 건너뛰고 소리가 든 파일을 원본영상/ 에 둔다)
python3 $S/transcribe.py "<작업 폴더>" [--model small] [--lang ko|en] [--from 초 --to 초]
python3 $S/subs_to_md.py "<작업 폴더>" && python3 $S/merge.py "<작업 폴더>"
```

- 결과 이름표는 「발화 원문 · 소리 받아쓰기(whisper)」다. 원래 말을 기계가 받아쓴 것이라 원문 인용에 쓸 수 있으나, 사람 이름 · 제품 이름 · 숫자는 화면 글자나 다른 출처로 맞댄다.
- `fetch.sh --video` 로 받은 720p 파일에는 소리가 없다. `transcribe.py` 는 소리가 든 파일이 없으면 `meta.json` 의 영상 주소로 소리만 한 번 더 받는다. 주소가 없는 영상은 소리가 든 원본 파일을 `원본영상/` 에 둔다(없으면 멈춘다).
- `transcribe.py` 는 `원본영상/` 안에서 소리가 든 첫 파일을 쓰고, 영상 번호는 `meta.json` 의 `id`, 없으면 그 폴더의 첫 파일 이름(밑줄 앞까지)이다. 결과는 `원본자막/<번호>.<언어>-whisper.json3` 이고 `subs_to_md.py` 가 같은 규칙으로 번호를 찾아 읽는다.
- `fetch.sh` 를 다시 돌리면 자막 출처 표가 새로 써지므로 `fetch.sh` 뒤에 `transcribe.py` 를 돌린다.
- 소리 받아쓰기 부품을 설치하지 못했으면 멈추고 알린다. 자막도 없고 화면에 읽을 글자도 없고 받아쓰기도 못 하면 말한 내용을 글로 옮길 수 없다고 알리고 멈춘다.

## 화면 글자 인식

```bash
bash $S/check_env.sh                                  # 글자 인식 부품 · CPU 수 · 지금 부하. 바쁨 경고가 나오면 --jobs 를 줄인다
bash $S/fetch.sh "<주소>" "<작업 폴더>" --video       # 720p, H.264 먼저
python3 $S/sample_frames.py "<작업 폴더>" 6           # 장면확인/ 그림. 거의 한 색인 장면은 건너뛴다
```

1. 장면 그림을 직접 보고 정한다.
   - 화면에 박힌 자막의 세로 위치 = **모든 자막 줄**(두 언어 두 줄이면 둘 다)의 맨 위부터 맨 아래까지 덮는 범위(화면 높이 대비, 예 0.76~0.96).
   - 슬라이드 · 도표 글자가 있나, 언어는 무엇인가. 한국어 모델은 영어 글자도 읽는다.
2. 시간 재기 = 본 실행과 같은 설정에 `--limit 20` 을 붙이되 `--jobs` 는 1 로만 한다(`--limit` 과 `--jobs` 2 이상은 같이 쓸 수 없고 프로그램이 오류로 멈춘다). 결과의 남은 시간은 거친 짐작이라고 알린다. 본 실행의 `--jobs` 를 늘리면 실제 시간은 이보다 줄어든다.
3. 본 실행은 백그라운드로 돌린다. 자막 영역과 화면 영역은 따로 본다(자막 = 약 0.25초마다 점 단위 바뀜 검사, 화면 = 0.5초마다 평균 차이). 기본값을 쓰고, 훑는 간격을 늘려 시간을 줄이지 않는다.
   ```bash
   python3 $S/screen_ocr.py "<작업 폴더>" --lang korean --band 0.76 0.96 [--from 초 --to 초] --jobs <CPU 수 ÷ 6> > "<작업 폴더>/화면글자_진행기록.txt" 2>&1
   ```
   - `--jobs` 는 영상을 구간으로 나눠 동시에 읽고 끝나면 합친다. 글자 인식 한 벌이 CPU 여섯 개쯤을 쓰므로 CPU 수를 6 으로 나눈다. `check_env.sh` 가 지금 부하가 CPU 수보다 높다고(바쁨) 경고하면 `--jobs` 를 줄이거나 부하가 내려간 뒤 돌린다.
   - `--jobs 1` 은 끊겨도 같은 명령을 다시 돌리면 이어 읽는다. `--jobs` 2 이상은 이어 읽지 못하고 처음부터 다시 읽는다. 설정을 하나라도 바꾸면 어느 쪽이든 처음부터다.
   - 끝나면 `화면글자_OCR_원본.json` 과 함께 `분석/구간_본.json`(읽은 것 전부)이 생긴다. 놓침 검산이 이 파일을 쓴다.
   - 같은 작업 폴더에서 두 개를 동시에 돌리지 않는다(잠금이 막는다).
   - 영상을 구간으로 나눠 따로 돌릴 때는 두 번째부터 `--out-name <이름>` 을 준다. 이름 없이 다시 돌릴 때 설정이 이전과 다르면 이미 있는 `화면글자_OCR_원본.json` 을 덮어쓰는 것을 프로그램이 막는다. 설정이 같으면 막지 않고 그대로 덮어쓴다(같은 결과). `--out-name` 결과는 `분석/` 아래에만 저장되고, 여러 구간 결과를 하나로 합치는 일은 손으로 한다(구간별 파일을 시각 순으로 이어 붙인 뒤 `merge.py`). 자동으로 합치는 옵션은 없다. 한 번에 다 읽으려면 구간을 나누지 말고 `--jobs` 를 늘린다.
   - 같은 자리에서 같은 줄을 여러 번 읽었는데 글자가 조금씩 다르면, `읽기용.md` 에는 가장 많이 나온 글자열을 쓴다(같은 수면 인식 점수가 높은 쪽). `영상_전체텍스트.md` 와 `화면글자_OCR_원본.json` 에는 읽은 그대로 남는다.
   - 글자 인식 모델은 기본값(`--lang korean` 이면 글자 자리 찾기 `PP-OCRv5_server_det` + 글자 읽기 `korean_PP-OCRv5_mobile_rec`)을 쓴다. `--det-model` · `--rec-model` 로 바꿀 수 있지만, 같은 영상 30초를 견줘 보니 글자 자리 찾기만 가벼운 `PP-OCRv5_mobile_det` 로 바꾼 쪽은 약 5배 빨랐어도 정답 자막 30줄 가운데 14줄을 놓쳤다(기본은 세 번 모두 1줄). 한쪽 모델만 주면 다른 쪽은 프로그램이 기본값으로 고정한다. 빠르기 때문에 모델을 바꾸지 않는다. 모델을 바꾸면 이어 읽기는 처음부터 다시 한다.
4. **놓침 검산.** 본 실행이 읽은 구간 안에서 30~40초 하나를 정답 모드(모든 장면의 자막을 읽는다)로 읽고 본 실행과 맞댄다. 맞대는 것은 자막 영역뿐이라 `--band` 를 본 실행과 같은 값으로 준다.
   ```bash
   python3 $S/screen_ocr.py truth "<작업 폴더>" --from 0 --to 40 --out-name t1 --band 0.76 0.96
   python3 $S/screen_ocr.py compare "<작업 폴더>" --truth t1 --runs 본 --from 0 --to 40
   ```
   - 「run 에 없는 줄 0개」여야 통과다. 놓친 줄이 있으면 `compare` 가 오류 종료(실패)로 끝난다. 그 시각의 장면을 눈으로 한 번 보고, 진짜 자막이면 문턱(`--band-pix`)을 낮춰 다시 돌린다. 실패로 끝났는데 「빠짐없다」고 쓰지 않는다.
5. 끝나면 `merge.py` 를 다시 돌린다. 화면 글자 검산 줄의 「찍혀야 할」과 「찍힌」이 같아야 통과다. 자막에 없고 화면에만 있던 내용은 `발표자방법.md` 에 먼저 더하고 항목표는 거기서 나오게 한 뒤, 한 줄로 알린다.
6. 보고에 남는 위험을 적는다 = 화면 영역은 확대 · 이동하는 순간을 사이사이 못 읽을 수 있다. 화면 영역에는 놓침 검산이 없다.

## 막힐 때

- 429(요청이 너무 많다) = 막힌 것이지 못 받는 것이 아니다. `fetch.sh` 가 0초 · 30초 · 90초 쉬며 세 번 시도하고, 세 번 다 막히면 멈추고 「10분 뒤 같은 명령을 다시 돌려라」를 찍는다. 클로드가 10분을 기다렸다 같은 명령을 한 번 더 돌린다(기다리는 코드는 없다). 영상 파일 받기(`--video`)가 막히면 그 안내 없이 멈추니 같은 방식으로 다시 돌린다. 같은 자막을 이미 받아 뒀으면 다시 받지 않는다(같은 요청을 또 하면 더 막힌다). 영상 여러 개를 연달아 받을 때는 영상 사이에 몇 분 쉰다. 유튜브가 아닌 사이트가 막히면 막힌 사이트를 읽는 웹 글 읽기 도구가 있을 때 그것으로 넘긴다.
- `sample_frames.py` 「첫 장면을 못 읽었다」 = 압축 방식이 AV1 → 영상 파일을 지우고 `fetch.sh --video` 다시.
- 글자 인식 부품을 못 부르면 `check_env.sh` 가 찍는 갈래별 안내대로 한다(paddleocr 가 없으면 설치 명령, urllib3 계열 오류면 스킬 전용 부품 폴더 명령, cv2 가 없으면 opencv-python 설치). 사용자 부품 폴더(`~/.local`)의 부품은 고치지 않는다. 스킬 전용 부품 폴더 만드는 법은 `check_env.sh` 가 안내한다.
- 원본(`자막_전문.md` · `영상_전체텍스트.md` · `화면글자_OCR_원본.json`)은 지우거나 덮지 않는다. 필요 없는 글자는 읽을 때만 거른다.
