# 2단계 — 이해 + 발표자방법.md + 항목표

## 1. 읽고 발표자방법.md 를 먼저 쓴다

`읽기용.md` 를 처음부터 끝까지 읽고 작업 폴더에 `발표자방법.md` 를 먼저 쓴다. 칸은 다섯이다.

1. 발표자가 풀려는 문제(원문 시각).
2. 방법 흐름 = 걸음마다 번호 · 무엇을 · 누가 · 도구 · 원문 시각. 발표자가 실제로 쓰는 순서로 적는다. 낱말 뜻도 여기서 잡고, 「이미 있나」는 그 뜻과 같은 것만 센다.
3. 쓰면 무엇이 달라진다고 했나 = 숫자 · 장면. 없으면 「원문에 없음」.
4. 시각 구간표 = 처음부터 끝까지 빈틈없이. 구간마다 걸음 번호 또는 「방법과 무관 — 까닭 한 줄」. 빈 구간이 있으면 다 읽지 않은 것이다.
5. 하지 말라고 한 것(원문 시각).

원문 시각과 인용은 발표자의 원래 말과 화면 글자에서만 가져온다. 자동 더빙 받아쓰기로 먼저 파악한 내용이 섞이면 그 줄을 원래 말과 다시 맞대고, 맞댈 수 없으면 「더빙 받아쓰기 기준」이라고 표시한다.

### 부분만 읽을 때

영상을 시각으로 나눠 부분만 읽는 길이면(`_1부` 등), 나머지 구간도 한 번 훑는다. 챕터 제목과 자막을 빠르게 읽으며 「하지 말라」 · 「주의」 · 「안 된다」 · 「대신」 같은 말이 있는지만 찾는다. 찾은 것은 `발표자방법.md` 5번 칸에 「부분 밖 — 원문 시각」으로 적는다. 훑었는데 없으면 「부분 밖에 하지 말라는 말 없음(훑은 구간)」이라고 한 줄 적는다.

## 2. 항목표를 만든다

작업 폴더에 `항목표.md`(부분이면 `항목표_1부.md`)를 만든다.

| 번호 | 걸음 번호(발표자방법.md) | 영상이 권한 행동 | 원문 시각 | 내 일에서 이 걸음이 일어나는 순간 | 이미 있나 | 누가 하는 행동인가 | 가져올 / 버릴 후보 | 이유 |

- 「내 일에서 이 걸음이 일어나는 순간」 = 0단계에서 받은 문제가 실제로 일어나는 어느 순간에 이 걸음이 끼어드는지. 영상 속 예는 내 환경의 실제 이름으로 바꾼 것이고, 내 프로젝트의 코드나 화면은 실제 파일을 열어 확인한 이름으로만 채운다.
- 「이미 있나」는 직접 찾아 파일:줄과, 그것이 발표자 걸음과 같은 일을 하는지 한 줄을 적는다. 볼 곳 = 0단계 문제가 일어나는 자리 · 클로드 규칙 파일(`CLAUDE.md`) · 이 창의 스킬 목록 전체(플러그인 안쪽 포함) · 기억 목록 · `settings.json` · 훅 설정. 개인 설정 파일(`video-to-claude.local.md`)이 더 볼 자리를 정했으면 그곳도 본다. 일부만 같으면 「부분 있음 — 없는 것」.
- **읽기만 하는 것과 직접 고치는 것은 다른 일이다.** 발표자의 걸음이 「리뷰어가 코드를 직접 고쳐 커밋한다」인데 내 환경에 있는 것이 「검토자가 읽고 지적만 한다」라면 같은 일이 아니다. 「이미 있나」에 적을 때 걸음마다 고치는 행동인지 읽기만 하는 행동인지 적고, 다르면 「부분 있음 — 직접 고치는 쪽이 없음」으로 둔다.
- 사용자가 치는 명령(`/clear` · `/model` 등)은 클로드 설정에 넣어도 달라지지 않는다.
- 버림이면 「이유」에 ① 발표자가 이 걸음을 하는 까닭(원문 시각) ② 「이미 있음」이면 파일:줄 · 하는 일 · 발표자 걸음과 같은 일인지 ③ 기억 · 규칙이면 그때 무엇을 정할 때(날짜 · 하던 일) ④ 버리면 `발표자방법.md` 3번 효과 중 사라지는 것을 모두 적는다. 버리는 이유는 ⓐ이미 있음(어디) ⓑ내 환경과 안 맞음(어떻게 — 그 일이 내 환경에 아예 없을 때만) ⓒ목적과 무관. 규칙과 부딪히면 버리지 않고 「부딪힘」으로 표시해 3단계에서 여쭙는다. 문제와 안 닿는 걸음도 항목표에서 빼지 않고, 버리면 ⓒ와 그 까닭을 적는다.

## 3. 화면을 띄우기 전에 검토한다

`발표자방법.md` 와 항목표를 만든 쪽이 아닌 눈으로 한 번 검토한다. 다른 모델이나 새 에이전트가 있으면 결과물만 주고 「처음 보는 사람 눈으로 이해 안 가는 곳 · 문제 생길 곳 · 논리가 끊긴 곳 · 근거 없이 단정한 곳」을 찾게 한다. 없으면 새 대화에서 파일만 읽게 한다. 지적은 내가 직접 확인한 뒤 반영한다.

## 4. 사용자에게 보여 드린다

`발표자방법.md` 와 가져올 · 버릴 후보를 보여 드린다. 쉬운 설명 화면을 만드는 스킬(예 `/eli5`)이 있으면 그것으로, 없으면 짧은 글로 한다. 버릴 후보 장면 = 발표자 까닭 → 지금 그 일을 어떻게 하나 → 그래서 버린다. 맨 끝 결정 장면에서 한 번만 여쭙는다 = 「버릴 후보 가운데 되살릴 것이 있으신가요」.

- 설명 화면을 만들었으면 장면마다 그림이 대본과 맞는지 화면을 찍어 직접 본다. 일감을 준 쪽에는 장면마다 그림이 무엇을 그렸는지 한 줄을 받는다. 숫자 기준(도형 몇 개)만 맞추려고 같은 도형 묶음을 반복했으면 실패로 보고 다시 만든다.

## 5. 길이 「정리」까지면 여기서 끝낸다

길_고르기.md 의 2번 길은 여기서 끝낸다. 판단 · 설계 · 전수 · 적용 길은 `길_고르기.md` 대로 이어간다.
