# 5~7단계 — 검토 + 초안 · 시험 · 설치 · 앞으로 쓰는 법

## 5. 검토 + 초안 (실제 자리에는 아직 넣지 않는다)

1. 설계(결정 + 넣을 곳)를 서로 다른 눈 셋에 동시에 맡긴다. 다른 모델이나 새 에이전트를 쓰고, 없으면 새 대화 셋을 쓴다. 맡기는 것은 ①원문과 다른 곳(결정마다 원문 시각 앞뒤 챕터를 뽑아 붙이고 원문 파일 경로도 준다) ②이대로 만들면 안 돌아갈 곳 ③0단계 문제와 안 맞게 옮긴 곳이다. 결과는 내가 확인한 뒤 받거나 버린다.
2. 초안은 전부 작업 폴더 `초안/` 아래에 만든다. 바꿀 실제 파일은 `초안/…/원본/` 에 복사하고 사본을 고친다. 다른 에이전트에 넘기는 일감은 파일로 저장해 넘긴다.
3. 초안을 만들지 않은 쪽에 결과물만 주고 한 번 더 검토를 받는다. 지적은 내가 확인한 뒤 손본다.
4. 읽기만 하는 검토와 직접 고치는 일을 섞지 않는다. 검토를 맡길 때는 「고치지 말고 지적만」이라고 적고, 고치는 일은 따로 맡긴다.

## 6. 시험 (서명 전, 따로 만든 시험 자리에서)

시험 자리 = 새 집 폴더 + 새 설정 폴더, 로그인 정보와 설정만 복사하고 훅 · 플러그인 · 상태줄은 지운다. 실제 환경에서 묻는 시험은 초안을 넣든 안 넣든 통과해 버리므로 쓰지 않는다.

```bash
C="${CLAUDE_CONFIG_DIR:-$HOME/.claude}"
H=$(mktemp -d <임시 폴더>/home.XXXX); mkdir -p $H/.claude
for f in .credentials.json settings.json; do [ -f "$C/$f" ] && cp "$C/$f" $H/.claude/; done   # 없는 파일은 건너뛴다
[ -f $H/.claude/settings.json ] && python3 -c "import json; p='$H/.claude/settings.json'; d=json.load(open(p)); [d.pop(k,None) for k in ('hooks','enabledPlugins','statusLine')]; json.dump(d,open(p,'w'))"
# 초안 넣기 = 규칙 $H/.claude/CLAUDE.md · 스킬 $H/.claude/skills/<이름>/ · 훅 $H/.claude/settings.json 의 hooks · 플러그인은 4_넣을곳.md 의 자리(플러그인 폴더 + 그 hooks.json)대로
cd $H && HOME=$H CLAUDE_CONFIG_DIR=$H/.claude claude -p "<질문>" --allowedTools <필요한 도구> --output-format json < /dev/null
```

- 시험 질문은 0단계에서 받은 문제와 묶는다. 그 문제가 실제로 일어나는 순간(예 「요청서를 올릴 때」)을 그대로 질문으로 만든다. 문제와 안 묶인 질문은 설치한 것이 문제를 풀었는지 말해 주지 못한다.
- 같은 질문을 넣기 전 · 넣은 뒤 두 자리에 던진다. 넣기 전에도 통과하면 질문을 바꾼다.
- 훅 = 걸려야 하는 상황을 만들어 실제로 막히는지 본다. 켜면 풀리는지, 서브에이전트에게 시킨 것도 같은지 본다.
- 스킬 = 실제로 불러 한 바퀴 돈다. 실제 자리 파일을 부르는 스킬이면 설치 뒤에 돈다.
- 결과를 `시험_6단계/` 에 남기고 보여 드린다(설명 화면 스킬이 있으면 그것으로). 마지막 장면이 서명 결정 장면이다. 설명 화면의 그림이 대본과 맞는지는 `2_정리_항목표.md` 4번처럼 화면을 찍어 확인한다.

## 7. 서명 → 설치 → 새 창 확인 → 앞으로 쓰는 법

1. 서명 = 사용자가 결정 장면에서 승인한 것을 확인하고, 그 시각과 함께 결정 문서 끝에 적는다.
2. **설치 직전에 실제 파일을 `초안/…/원본/` 사본과 대조한다.** 다르면 다른 창이 그사이 고친 것이니 합친 뒤 다시 시험한다.
3. 바꿀 실제 파일을 작업 폴더 `백업/` 에 복사한 뒤, 같은 폴더에 새 이름으로 복사하고 `mv` 로 바꿔 끼운다(돌고 있는 창이 깨지지 않게).
4. 실제 환경 새 창(`claude -p`)에서 6단계와 같은 시험을 다시 한다. 이미 켜진 창에는 새 훅 · 플러그인이 다시 열 때부터 걸린다는 것과, 스크립트 변경은 모든 창에 바로 걸린다는 것을 알린다.
5. 판본 관리 = 플러그인 · 스킬 폴더를 깃 저장소로 두고 커밋 다섯 칸(무엇 · 왜 · 근거 · 영향 · 되돌리기)에 고친 까닭을 적는다. 깃허브 같은 바깥 저장소에 처음 올리는 것은 사용자에게 여쭌 뒤에만 한다.
6. 기억 한 줄(위치 · 켜는 법 · 되돌리기)을 남긴다. 작업 폴더에 남기는 것 = 글 파일 · 항목표 · 결정 · 검토 결과 · 초안 · 시험 · 백업 · `이어받기*.md`.
7. **「앞으로 이렇게 쓰세요」 한 장을 만들어 보여 드린다.** 설치가 끝나도 쓰는 법을 모르면 쓰이지 않는다. 한 장에 세 칸만 적는다.
   - 무엇이 바뀌었나 = 설치한 것을 한 줄씩(어디에 무엇이 들어갔나).
   - 언제 저절로 걸리나 = 사용자가 아무것도 안 해도 작동하는 때(예 「요청서를 올릴 때 이 검사가 자동으로 돈다」), 새 창부터인지 지금 창에서도 되는지.
   - 사용자가 칠 말 = 직접 불러야 하는 것의 정확한 말(슬래시 명령이나 문장 예시) 두세 개와, 되돌리는 말 한 줄.
   `이어받기*.md` 와 함께 작업 폴더에 `앞으로_이렇게_쓰세요.md` 로 남긴다.
